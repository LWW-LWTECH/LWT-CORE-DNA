LWT Core: DNA

Overview

The Core: DNA library is designed to provide a robust foundation for building modern web applications, offering a suite of reusable components and utilities.

Developed by Lee W Winter as part of the LWW-LWTECH initiative to support buisness app development.

The library is provided with an open-source MIT License, allowing developers to freely use and integrate it into their projects. If there are any suggestions or needs for additional elements please contact the developer. https://lwinter.tech

Implementation

All libraries need the core library "lwt-core.js" to be loaded first. Make sure to include it before any other library scripts in your HTML document.
The lwt-core.css is optional since layout css is included inline when you call the element, but recommended for consistent styling across components colors and other css variables. 

<head>
    <script src="https://cdn.jsdelivr.net/gh/LWW-LWTECH/LWT-CORE-DNA@refs/heads/main/lwt-core.js" type="text/javascript"></script>
    <script src="https://cdn.jsdelivr.net/gh/LWW-LWTECH/LWT-CORE-DNA@refs/heads/main/lwt-general.js" type="text/javascript"></script>
    <script src="https://cdn.jsdelivr.net/gh/LWW-LWTECH/LWT-CORE-DNA@refs/heads/main/lwt-forms.js" type="text/javascript"></script>
    <script src="https://cdn.jsdelivr.net/gh/LWW-LWTECH/LWT-CORE-DNA@refs/heads/main/lwt-dashboard.js" type="text/javascript"></script>

    <link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/LWW-LWTECH/LWT-CORE-DNA@refs/heads/main/lwt-core.css">
</head>

General Elements

These elements are part of the CDNA general library. A growing collection of custom Web UI components for building modern web applications.


Accordion

An accordion element is a vertically stacked list of headers that users can click to reveal or hide associated content sections. It acts exactly like a physical accordion, expanding and collapsing on demand to save screen space.

Example: Single

Allows only one accordion item to be expanded at a time.

Accordion Item 1
Content for Accordion Item 1
Accordion Item 2
Content for Accordion Item 2

Example: Multiple

Allows multiple accordion items to be expanded simultaneously.

Accordion Item 1
Content for Accordion Item 1
Accordion Item 2
Content for Accordion Item 2

Implementation

<lwtg-accordion>
    <lwtg-accordion-item>
        <div slot="label">Accordion Item 1</div>
        <div slot="body">Content for Accordion Item 1</div>
    </lwtg-accordion-item>
    <lwtg-accordion-item>
        <div slot="label">Accordion Item 2</div>
        <div slot="body">Content for Accordion Item 2</div>
    </lwtg-accordion-item>
</lwtg-accordion>

Properties

Attributes:

  • multiple — (on <lwtg-accordion>) boolean — allow more than one item open at once. Default is single-open (opening one closes the others).
  • open — (on <lwtg-accordion-item>) read once at connect for the initial state. Toggling it later via setAttribute does not re-open/close the item — use the methods below.
  • disabled — (on <lwtg-accordion-item>) boolean, read once at connect; prevents toggling.

Slots:

  • label — (on <lwtg-accordion-item>) the clickable header content.
  • body — (on <lwtg-accordion-item>) the collapsible body content.

JS Properties:

  • isOpen — (on <lwtg-accordion-item>) read-only boolean.

Methods:

  • open() — opens this item.
  • close() — closes this item.
  • toggle() — toggles this item.

Events:

  • lwt-open / lwt-close — fired on the item when it opens/closes (no detail).

Theming: --lwt-accordion-chevron-color, --lwt-accordion-focus-color, --lwt-accordion-border, --lwt-accordion-bg.

Alerts

Alerts are used to provide feedback messages to the user. They can be of different variants such as success, warning, info, and error. This also has an option for title and dismissable.

Implementation

<lwtg-alert variant="success" title="Success" dismissible="true"> This is a success alert. </lwtg-alert>
    <lwtg-alert variant="warning" title="Warning"> This is a warning alert. </lwtg-alert>
    <lwtg-alert variant="info"> This is an info alert. </lwtg-alert>
    <lwtg-alert variant="error" dismissible="true"> This is a danger alert. </lwtg-alert>
This is a success alert. This is a warning alert. This is an info alert. This is a danger alert.

Properties

Attributes:

  • variant — "info" (default) | "success" | "warning" | "error".
  • title — optional bold heading above the message.
  • dismissible — boolean — shows a close button.

Methods:

  • close() — removes the alert from the DOM (emits lwt-close first). Dismissal is permanent.

Theming: --lwt-alert-bg, --lwt-alert-success-color, --lwt-alert-warning-color, --lwt-alert-info-color, --lwt-alert-error-color, --lwt-alert-title-color, --lwt-alert-text-color.

Buttons

Buttons are used to trigger actions. They can have different variants such as primary, secondary, and danger.

Implementation

<lwtg-button variant="primary">Primary Button</lwtg-button>
<lwtg-button variant="secondary">Secondary Button</lwtg-button>
<lwtg-button variant="danger">Danger Button</lwtg-button>
Primary Button Secondary Button Danger Button

Properties

Attributes:

  • variant — "primary" | "secondary" | "danger".
  • size — "sm" | "lg".
  • disabled — boolean.
  • label — fallback text (overridden by slot="label" or default-slot content).

Slots:

  • cta / label — named slots for richer content than the plain text attributes allow.

Events:

  • lwt-click — fires on click when not disabled; detail: { originalEvent }.

Theming: --lwt-primary, --lwt-secondary, --lwt-danger, --lwt-btn-radius, --lwt-focus-color.

Cards

Cards are used to display content in a structured format, often including an image, label, body content, and a call-to-action button.

Implementation

<lwtg-card image="image-url" image-alt="Image Alt Text" label="Card Label">
    <p>Card body content goes here.</p>
</lwtg-card>

This is a Sound Set product, perfect for your audio needs.

This is a Spar Day product, perfect for your daily needs.

Cosmetic skincare product designed to enhance beauty.

soHERBs Charantia Cleansing Gel, for acne-prone skin.

Properties

Attributes:

  • image — image URL; the image block is omitted entirely if unset.
  • image-alt — alt text for the image.
  • image-position — "top" (default) | "bottom".
  • label — fallback heading text (overridden by slot="label").

Slots:

  • label — heading; falls back to the label attribute.
  • (default) — body content — any HTML, not just text.
  • cta — call-to-action content, typically an <lwtg-button>.

Theming: --lwt-card-bg, --lwt-card-border, --lwt-card-radius, --lwt-card-shadow, --lwt-card-padding, --lwt-card-image-height, --lwt-card-label-color, --lwt-card-body-color, --lwt-card-gap.

Image Grid

The image grid component allows you to display a series of images in a grid layout. You can control the number of columns, rows, gap between items, and the height of each row. Then each grid item can be told to span columns or rows.

Implementation

<lwtg-image-grid columns="4" rows="2" gap="12px" row-height="180px">
        <lwtg-grid-item  col-span="1"   row-span="2"    src="img_url_here.jpg" label="Alpha"></lwtg-grid-item>
        <lwtg-grid-item  col-span="2"   row-span="1"    src="img_url_here.jpg" label="Beta"></lwtg-grid-item>
        <lwtg-grid-item  col-span="1"   row-span="2"    src="img_url_here.jpg" label="Beta"></lwtg-grid-item>
        <lwtg-grid-item  col-span="1"   row-span="1"    src="img_url_here.jpg" label="Delta"></lwtg-grid-item>
        <lwtg-grid-item  col-span="1"   row-span="1"    src="img_url_here.jpg" label="Delta"></lwtg-grid-item>
    </lwtg-image-grid>

Properties

Attributes:

  • columns — (on <lwtg-image-grid>) target/max column count; omit for responsive auto-fill mode.
  • rows — (on <lwtg-image-grid>) fixed row count; combined with columns it becomes a hard cap.
  • gap — (on <lwtg-image-grid>) CSS length between cells (default 1rem).
  • row-height — (on <lwtg-image-grid>) CSS length for every implicit row (default 160px).
  • dense — (on <lwtg-image-grid>) boolean; grid-auto-flow: dense, backfills gaps left by spanning items.
  • src — (on <lwtg-grid-item>) image URL, base64/data URI, or a YouTube URL.
  • href — (on <lwtg-grid-item>) optional link URL; wraps the rendered image in an <a>.
  • type — (on <lwtg-grid-item>) "image" (default) | "svg" | "embed"; YouTube is auto-detected from src.
  • label — (on <lwtg-grid-item>) caption overlay shown on hover/focus.
  • col-span / row-span — (on <lwtg-grid-item>) how many columns/rows this cell spans.
  • play-inline — (on <lwtg-grid-item>) boolean, YouTube only; swaps the thumbnail for a live autoplaying iframe on click.

Slots:

  • (default) — (on <lwtg-grid-item>) raw content for "svg" (no src) and "embed" types.

Events:

  • lwt-click — (on <lwtg-grid-item>) fired on click/Enter/Space; detail: { type, src, label, index }.
  • lwt-play — (on <lwtg-grid-item>) YouTube + play-inline only; detail: { videoId }.

Theming: --lwt-image-grid-gap, --lwt-image-grid-row-height, --lwt-image-grid-min-width, --lwt-grid-item-radius, --lwt-grid-item-bg, --lwt-grid-item-label-bg, --lwt-grid-item-label-color.

            <lwtg-button variant="secondary" data-lwt-dismiss>Cancel</lwtg-button>
        </div>
    </lwtg-modal>

Properties

Attributes:

  • label — the dialog's accessible label/heading.
  • open — present at parse time auto-opens on connect; not reactive afterward — use .show()/.close().
  • no-dismiss — boolean; disables closing via backdrop click or Escape, for modals requiring an explicit action.

Slots:

  • (default) — any content — headers, paragraphs, action buttons.

Methods:

  • toggle() — toggles open/closed.

Events:

Icon

Renders a single SVG icon fetched from the library's icon set (first from this repo's GitHub raw host, then falling back to a local /icons path). Used throughout this page for the little icons in each section's summary.

Implementation

Properties

Attributes:

  • height — CSS length for the rendered icon (default 24px).

Properties

Attributes:

  • dot-as-image — boolean; renders each dot as a small square thumbnail of that card's own image instead of a plain circular dot.
  • image-position — optional; if set, synced onto every <lwtg-card> child ("top"/"bottom").

  • next() — advances one slide.

Events:

Grid

A general-purpose CSS Grid layout container for arbitrary page content — set a target column count and minimum column width, and it wraps automatically with no media queries. Any child can opt into spanning via data-col-span/data-row-span (2–8 or "full", and 2–6 respectively). This is the mixed-content counterpart to Image Grid below, which is tuned for uniform media cells instead.

Implementation

<lwtg-grid columns="4" gap="12px" min-col-width="140px">
    <div style="background:#eef2ff;padding:12px;border-radius:6px;">Item 1</div>
    <div style="background:#eef2ff;padding:12px;border-radius:6px;">Item 2</div>
    <div style="background:#eef2ff;padding:12px;border-radius:6px;" data-col-span="2">Wider item, spans two columns</div>
    <div style="background:#eef2ff;padding:12px;border-radius:6px;">Item 4</div>
    <div style="background:#eef2ff;padding:12px;border-radius:6px;">Item 5</div>
</lwtg-grid>
Item 1
Item 2
Wider item, spans two columns
Item 4
Item 5

Properties

Attributes:

  • columns — target/maximum column count. Omit for pure responsive mode (auto-fit at min-col-width).
  • rows — fixed row count with equal (1fr) heights. Omit to let rows size to their content.
  • gap — CSS length between cells (default 1rem).
  • min-col-width — minimum column width before wrapping (default 200px) — governs when the layout collapses to fewer columns.
  • row-height — fixed height for every implicit row (default "auto").
  • dense — boolean; grid-auto-flow: dense — lets smaller items backfill gaps left by spanning items.

Slots:

  • (default) — any children you want laid out.

Theming: --lwt-grid-gap, --lwt-grid-row-height, --lwt-grid-min-col-width, --lwt-grid-columns, --lwt-grid-rows.

Grid Item media types

<lwtg-grid-item> (used above inside Image Grid) also resolves inline SVG and YouTube media automatically. This example shows a plain image, an inline/stylable SVG via the default slot, and an auto-detected YouTube video that swaps to a live, autoplaying iframe on click.

Implementation

<lwtg-image-grid columns="3" gap="12px" row-height="160px">
    <lwtg-grid-item src="https://i.pravatar.cc/400?img=20" label="Photo"></lwtg-grid-item>
    <lwtg-grid-item type="svg" label="Inline SVG">
        <svg viewBox="0 0 24 24" width="48" height="48" fill="#3b82f6"><circle cx="12" cy="12" r="10"/></svg>
    </lwtg-grid-item>
    <lwtg-grid-item src="https://youtu.be/dQw4w9WgXcQ" label="YouTube video" play-inline></lwtg-grid-item>
</lwtg-image-grid>

Properties

Attributes:

  • src — image URL, base64/data URI, or a YouTube URL.
  • href — optional link URL; wraps the rendered image in an <a target="_blank">.
  • video-id — explicit YouTube video id; skips URL parsing, takes priority over src.
  • type — "image" (default) | "svg" | "embed" — forces resolution; YouTube detection from src/video-id always wins regardless.
  • alt — alt text for the rendered <img>.
  • label — caption shown as an overlay on hover/focus; omitted entirely from the DOM when unset.
  • col-span — how many grid columns this cell spans (default 1; 2–8 or "full").
  • row-span — how many grid rows this cell spans (default 1; 2–6).
  • play-inline — boolean, YouTube only; clicking swaps the thumbnail facade for a live autoplaying iframe in place.

Slots:

  • (default) — raw content for "svg" (no src) and "embed" types — the only way to get a stylable, currentColor-aware SVG.

Events:

  • lwt-click — detail: { type, src, label, index }.
  • lwt-play — YouTube + play-inline only; detail: { videoId }.

Theming: --lwt-grid-item-radius, --lwt-grid-item-bg, --lwt-grid-item-label-bg, --lwt-grid-item-label-color, --lwt-grid-item-focus-color.

Nav Menu

A page main-menu container (<lwtg-nav-menu>) that coordinates <lwtg-nav-item> entries: horizontal/vertical layout, hover or tap-to-open dropdowns at any nesting depth, and a responsive collapse into a hamburger + off-canvas panel below a breakpoint.

Implementation

<lwtg-nav-menu orientation="horizontal" breakpoint="880" aria-label="Main">
    <lwtg-nav-item href="#" active>Home</lwtg-nav-item>
    <lwtg-nav-item label="Products">
        <lwtg-nav-item href="#">Product A</lwtg-nav-item>
        <lwtg-nav-item href="#">Product B</lwtg-nav-item>
    </lwtg-nav-item>
    <lwtg-nav-item href="#">About</lwtg-nav-item>
    <lwtg-nav-item href="#" disabled>Disabled</lwtg-nav-item>
</lwtg-nav-menu>
Home Product A Product B About Disabled

Properties

Attributes:

  • orientation — (on <lwtg-nav-menu>) "horizontal" (default) | "vertical". Synced onto every child <lwtg-nav-item>.
  • sticky — (on <lwtg-nav-menu>) boolean; sticks the bar to the top of its nearest scrolling ancestor.
  • breakpoint — (on <lwtg-nav-menu>) px width below which the menu switches to a hamburger/off-canvas mobile mode (default 880).
  • href — (on <lwtg-nav-item>) if set (and the item has no children), renders an <a>; otherwise a <button>.
  • target — (on <lwtg-nav-item>) anchor target, e.g. "_blank".
  • label — (on <lwtg-nav-item>) fallback text (overridden by slot="label").
  • disabled — (on <lwtg-nav-item>) boolean; blocks all interaction.
  • active — (on <lwtg-nav-item>) boolean; visual "current page" indicator — set by hand, no routing detection is done for you.

Slots:

  • label — (on <lwtg-nav-item>) named slot for rich label content.
  • (default) — (on <lwtg-nav-item>) nested <lwtg-nav-item> children, which makes this item a dropdown parent automatically.

JS Properties:

  • isOpen, labelText — (on <lwtg-nav-item>) read-only.

Methods:

  • closeAll() — (on <lwtg-nav-menu>) closes every open dropdown branch.
  • open() / close() / toggle() / focusTrigger() — (on <lwtg-nav-item>) control a dropdown parent.

Events:

  • lwt-navopen / lwt-navclose — (on <lwtg-nav-item>) fired on a dropdown parent; bubble up and are used by <lwtg-nav-menu> to coordinate single-open-per-level.
  • lwt-select — (on <lwtg-nav-item>) leaf items only; detail: { href, label }.

Theming: --lwt-nav-item-color, --lwt-nav-item-hover-bg, --lwt-nav-item-active-bg, --lwt-nav-menu-gap, --lwt-nav-menu-z, --lwt-nav-dropdown-bg/-border/-shadow.

    QR Code

    A QR code generator encoded entirely client-side — no image service or external library — from a from-scratch ISO/IEC 18004 implementation (byte-mode encoding, Reed-Solomon error correction, automatic version selection, penalty-scored mask selection). The version/size is picked automatically to fit src at the requested level.

    Implementation

    <lwtg-qr src="https://www.lwinter.tech" size="180" level="H"
    color="#111827" background-color="#f9fafb" corner-color="#2563eb" radius="0.3"></lwtg-qr>

    Properties

    Attributes:

    • src — required; the text to encode (URL or any string), encoded as UTF-8 byte-mode data.
    • size — rendered width/height in px, square (default 200).
    • level — error correction "L" | "M" (default) | "Q" | "H" — higher tolerates more damage/obstruction at the cost of a bigger code.
    • background-color — quiet zone + light module color (default #ffffff).

    • tooltip — "none" (default) | "hover" | "always".

    JS Properties:

    • value — get/set array of numbers, one per handle; setting a longer/shorter array changes the handle count.
    • formatLabel — assignable function(value) -> string; overrides label-format for both ticks and tooltips.

    Methods:

    • focus() / blur() / checkValidity() / reportValidity() — standard helpers; focus/blur proxy to the first handle.

    Events:

    • lwt-input — every value change while dragging/stepping; detail: { value, index }.
    • lwt-change — a drag/keyboard interaction ends with a changed value, or .value was set; detail: { value }.

    Form participation: uses ElementInternals — submits one form entry per handle under name.

    Transfer List

    A two-column "available / selected" picker — highlight items on the left, click Add to move them right (or double-click), Remove to send them back, and optionally reorder the right column with Move Up/Down. The classic dual-listbox pattern for report column pickers or sort-order builders.

    Implementation

    <lwtf-transfer-list label="Fields" name="fields" sortable
    available-label="Available fields:" selected-label="Sort order:">
    <lwtf-transfer-option value="cars">Cars</lwtf-transfer-option>
    <lwtf-transfer-option value="children">Children</lwtf-transfer-option>
    <lwtf-transfer-option value="bikeBuyer" selected>BikeBuyer</lwtf-transfer-option>
</lwtf-transfer-list>
    Cars Children BikeBuyer

    Properties

    Attributes:

    • label, helper, error, name — display / form basics.
    • available-label — left column heading (default "Available").
    • selected-label — right column heading (default "Selected").
    • sortable — boolean; shows Move Up / Move Down buttons for reordering the right column.
    • size — visible row count of each listbox (default 8).
    • required — boolean; at least one item must end up in the selected column.
    • disabled — boolean; disables the whole control.

    JS Properties:

    • value — get/set array of selected values, in right-column order.
    • options — get/set the full item list as [{value, label, selected}]; setter replaces the entire universe of items.

    Methods:

    • setValue(newValues, opts) — {silent:true} to skip the lwt-change emit.
    • addOption(opt) / updateOption(value, patch) / removeOption(value) — build items from JS: {value, label, selected?}.
    • clear() / checkValidity() / reportValidity() — standard helpers.

    Events:

    • lwt-change — fires on Add, Remove, Move Up/Down, double-click, or a non-silent value/API change; detail: { value: [...] }.

    Form participation: uses ElementInternals, so name="…" submits one entry per selected value, in right-column order.

    Dashboard Elements

    These elements are part of the CDNA dashboard library (lwt-dashboard.js) — charts and KPI tiles rendered as inline SVG, with no external charting dependency. Most charts take their data through a JS .data property (a Chart.js-compatible shape) rather than attributes, since that data is structured, not a flat string; style options stay plain attributes.


    Bar Chart

    A bar chart rendered as inline SVG (no Chart.js dependency, but a Chart.js-compatible data shape), redrawn whenever .data or a style attribute changes. Supports grouped or stacked bars, horizontal orientation, and dashed goal/target reference lines.

    Implementation

    var chart = document.querySelector('lwtd-bar-chart');
chart.data = {
  labels: ['Q1', 'Q2', 'Q3', 'Q4'],
  datasets: [
    { label: 'Online',   data: [42, 58, 63, 71] },
    { label: 'In-Store', data: [65, 53, 48, 52], backgroundColor: '#f9a8d4', borderColor: '#ec4899' },
    { label: 'Wholesale', data: [28, 32, 35, 40] }
  ]
};

    Properties

    Attributes:

    • title — chart title text.
    • orientation — "vertical" (default) | "horizontal".
    • stacked — boolean; stacks datasets instead of grouping them.
    • legend-position — "top" (default) | "bottom" | "left" | "right" | "none".
    • grid — "both" (default) | "horizontal" | "vertical" | "none".
    • x-label / y-label — category / value axis titles.

    JS Properties:

    • data — set only — { labels: [...], datasets: [{ label, data, backgroundColor?, borderColor? }], targetLine?: {label,value,color?}, targetLines?: [...] }. Colors cycle through a built-in pastel palette when omitted.

    Theming: --lwt-chart-bg, --lwt-chart-grid, --lwt-chart-border, --lwt-chart-tick-color, --lwt-chart-title-color, --lwt-chart-legend-color, --lwt-chart-target-color, --lwt-chart-aspect-ratio (default 8/5).

    Bubble Chart

    Two numeric axes (x, y) plus a per-point radius (r), matching Chart.js's bubble format. Both axes auto-scale to "nice" numbers around the actual data range rather than forcing a zero baseline.

    Implementation

    var chart = document.querySelector('lwtd-bubble-chart');
chart.data = {
  datasets: [
    { label: 'North America', data: [{ x: 65, y: 7.8, r: 20 }, { x: 55, y: 7.5, r: 14 }, { x: 50, y: 7.0, r: 12 }] },
    { label: 'Europe', data: [{ x: 40, y: 8.2, r: 18 }, { x: 45, y: 8.0, r: 14 }, { x: 30, y: 7.6, r: 10 }] }
  ]
};

    Properties

    Attributes:

    • title — chart title text.
    • bubble-scale — multiplier applied to every point's r (default 1).
    • legend-position — "top" (default) | "bottom" | "left" | "right" | "none".
    • grid — "both" (default) | "horizontal" | "vertical" | "none".
    • x-label / y-label — axis titles.

    JS Properties:

    • data — set only — { datasets: [{ label, data: [{x, y, r}], backgroundColor?, borderColor? }] }. r is a literal pixel radius (not auto-scaled); tune via bubble-scale or directly in the data.

    Theming: --lwt-chart-bg, --lwt-chart-grid, --lwt-chart-border, --lwt-chart-tick-color, --lwt-chart-title-color, --lwt-chart-legend-color, --lwt-chart-aspect-ratio.

    Doughnut Chart

    Same data shape, colors, and legend as Pie Chart below, with an inner-radius attribute cutting a hole out of the middle. Implemented self-contained (not a subclass of the pie chart) so load order between element files never matters.

    Implementation

    var chart = document.querySelector('lwtd-doughnut-chart');
chart.data = {
  labels: ['Online', 'In-Store', 'Wholesale'],
  datasets: [{ data: [163, 218, 135] }]
};

    Properties

    Attributes:

    • title — chart title text.
    • legend-position — "right" (default) | "top" | "bottom" | "left" | "none".
    • inner-radius — 0–100, percentage of the outer radius the hole occupies (default 60). 0 behaves like a pie chart.

    JS Properties:

    • data — set only — { labels: [...], datasets: [{ data, backgroundColor?: string|array, borderColor?: string|array }] }. Only the first dataset is used.

    Theming: --lwt-chart-bg, --lwt-chart-border, --lwt-chart-title-color, --lwt-chart-legend-color, --lwt-chart-empty, --lwt-chart-aspect-ratio.

    Gauge

    A circular gauge/meter: one value against a min-max range drawn as a partial-circle progress arc (the speedometer silhouette) rather than a needle-and-dial. Simple values are plain attributes; threshold zones go through the .data property.

    Implementation

    <lwtd-gauge title="CPU Load" value="72" min="0" max="100" unit="%" label="current"></lwtd-gauge>

<script>
  // Optional: threshold zones (the colored bands on a speedometer)
  document.querySelector('lwtd-gauge').data = {
    zones: [
      { from: 0, to: 50, color: '#22c55e' },
      { from: 50, to: 80, color: '#f59e0b' },
      { from: 80, to: 100, color: '#ef4444' }
    ]
  };
</script>

    Properties

    Attributes:

    • title — small title above the gauge.
    • value — current value (also the displayed number, shown verbatim with unit appended — no number formatting).
    • min, max — range (defaults 0, 100).
    • label — small caption under the value, inside the ring.
    • unit — suffix appended to the displayed value, e.g. "%".
    • color — explicit arc color; overrides zone matching entirely.
    • thickness — ring stroke width in px (default 24).
    • sweep — degrees of arc the gauge spans, gap centered at the bottom (default 270; 180 gives a half-donut).

    JS Properties:

    • data — set only, optional — { zones: [{ from, to, color }] }. Without zones the track is plain grey and the progress arc uses color (or built-in blue). With zones, a small indicator marks the current value on the colored bands instead.

    Theming: --lwt-gauge-bg, --lwt-gauge-track-color, --lwt-gauge-color, --lwt-gauge-value-color, --lwt-gauge-label-color, --lwt-gauge-tick-color, --lwt-gauge-aspect-ratio.

    Line Chart

    Same conventions as Bar Chart with line/area-specific extras: per-dataset area fill, and chart-wide or per-dataset line width and point size. Points plot edge-to-edge (not centered in bands, unlike bars).

    Implementation

    var chart = document.querySelector('lwtd-line-chart');
chart.data = {
  labels: ['Jan','Feb','Mar','Apr','May','Jun'],
  datasets: [
    { label: 'Visitors', data: [4200, 4800, 5100, 4900, 5500, 6200] }
  ]
};
// multi-series + area fill: chart.setAttribute('fill', '');

    Properties

    Attributes:

    • title — chart title text.
    • stacked — boolean; stacks areas instead of overlapping them.
    • fill — boolean; chart-wide default fill mode for datasets that don't set their own.
    • line-width — default stroke width in px (default 2).
    • point-radius — default dot radius in px, 0 hides dots (default 3).
    • legend-position — "top" (default) | "bottom" | "left" | "right" | "none".
    • grid — "horizontal" (default) | "vertical" | "both" | "none".
    • x-label / y-label — axis titles.

    JS Properties:

    • data — set only — { labels, datasets: [{ label, data, borderColor?, backgroundColor?, fill?, borderWidth?, pointRadius? }] }. Per-dataset fields override the chart-wide attributes above.

    Theming: --lwt-chart-bg, --lwt-chart-grid, --lwt-chart-border, --lwt-chart-tick-color, --lwt-chart-title-color, --lwt-chart-legend-color, --lwt-chart-aspect-ratio.

    Pie Chart

    A pie chart rendered as inline SVG, same conventions as Bar Chart. Shows one series sliced by label — for grouped/stacked multi-series data use Bar Chart instead.

    Implementation

    var chart = document.querySelector('lwtd-pie-chart');
chart.data = {
  labels: ['Online', 'In-Store', 'Wholesale'],
  datasets: [{ data: [163, 218, 135], backgroundColor: ['#93c5fd', '#f9a8d4', '#86efac'] }]
};

    Properties

    Attributes:

    • title — chart title text.
    • legend-position — "right" (default) | "top" | "bottom" | "left" | "none".

    JS Properties:

    • data — set only — { labels: [...], datasets: [{ data, backgroundColor?: string|array, borderColor?: string|array }] }. Only the first dataset is used; colors cycle automatically when omitted.

    Theming: --lwt-chart-bg, --lwt-chart-border, --lwt-chart-title-color, --lwt-chart-legend-color, --lwt-chart-empty, --lwt-chart-aspect-ratio.

    Radar Chart

    Labels become axes (spokes) arranged evenly around a circle; each dataset is one value per axis, drawn as a closed, filled polygon — e.g. comparing skill ratings across people.

    Implementation

    var chart = document.querySelector('lwtd-radar-chart');
chart.data = {
  labels: ['Communication', 'Technical', 'Leadership', 'Creativity', 'Teamwork', 'Problem Solving'],
  datasets: [
    { label: 'Alice', data: [85, 82, 70, 90, 88, 65] },
    { label: 'Bob',   data: [78, 65, 80, 60, 72, 85] }
  ]
};

    Properties

    Attributes:

    • title — chart title text.
    • legend-position — "top" (default) | "bottom" | "left" | "right" | "none".
    • grid — "both" (default) | "none" — rings are polygons matching the axis count, not axis-aligned lines.
    • line-width — default stroke width in px (default 2).
    • point-radius — default dot radius in px, 0 hides dots (default 3).
    • fill-opacity — default fill alpha, 0–1 (default 0.25).

    JS Properties:

    • data — set only — { labels: [...axis names...], datasets: [{ label, data, borderColor?, backgroundColor?, pointRadius?, borderWidth?, fillOpacity? }] }. The radial scale auto-ranges to a "nice" min/max around the actual data (no begin-at-zero option) — needs at least 3 labels to look like a proper polygon.

    Theming: --lwt-chart-bg, --lwt-chart-grid, --lwt-chart-tick-color, --lwt-chart-title-color, --lwt-chart-legend-color, --lwt-chart-aspect-ratio.

    Sparkline

    A minimal inline trend line — no axes, grid, legend, or title, meant to sit inline in text or inside a small dashboard card (commonly paired with Stat Card below). Unlike the other charts, data is a plain data attribute, not a JS property.

    Implementation

    <lwtd-sparkline
    label="Weekly sales performance showing growth"
    data="10 25 15 40 30 45 35" trend
    style="height: 2rem; width: 160px;"></lwtd-sparkline>

    Properties

    Attributes:

    • data — required; space/comma separated numbers. A normal observed attribute — setAttribute('data', ...) live-updates it.
    • label — accessible label (aria-label on the SVG; not rendered as visible text).
    • color — CSS color, overrides everything including trend.
    • trend — boolean; auto-color green/red/grey by first-to-last value change (>5% rise/fall, else neutral).
    • no-fill — boolean; disables the area fill under the line (on by default).
    • line-width — stroke width in viewBox units (default 2).

    Theming: --lwt-sparkline-width (120px), --lwt-sparkline-height (32px), --lwt-sparkline-color, --lwt-sparkline-up-color, --lwt-sparkline-down-color, --lwt-sparkline-flat-color.

    Stat Card

    A KPI/stat card: label, big value, an optional colored delta, an optional icon, and an optional trailing chart — meant to pair naturally with Sparkline for the classic "number + trend line" dashboard tile.

    Implementation

    <lwtd-stat-card label="Revenue" value="$48,200" delta="+12.4%">
    <span slot="icon">💰</span>
    <lwtd-sparkline slot="chart" trend data="30 34 31 40 38 45 48"
        style="width: 100%; height: 28px;"></lwtd-sparkline>
</lwtd-stat-card>
    💰

    Properties

    Attributes:

    • label — small caption above the value.
    • value — the big stat text — plain display string, no number formatting (write "$48,200" exactly as you want it shown).
    • delta — change text, e.g. "+12.4%" (omit to hide the delta row).
    • trend — "up" | "down" | "neutral" — overrides inference from delta's leading character (+/-).

    Slots:

    • icon — anything — an emoji, inline SVG, an <img>. Row disappears automatically when empty.
    • chart — typically an <lwtd-sparkline>; size it directly on the sparkline itself via style, not via the card.

    Theming: --lwt-stat-bg, --lwt-stat-border, --lwt-stat-label-color, --lwt-stat-value-color, --lwt-stat-icon-bg (shares --lwt-sparkline-up/-down/-flat-color with Sparkline).
